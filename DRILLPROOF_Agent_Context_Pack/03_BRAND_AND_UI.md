# 03 — Brand and UI Direction

## Brand identity
**DRILLPROOF**  
**Prepared. Proven.**

The supplied logo uses a red shield / pulse / upward-arrow motif with a small flame element, paired with a black-and-red wordmark. Preserve the logo as supplied. Do not redraw, replace, or reinterpret it unless explicitly asked.

## Color direction
Use the existing red identity consistently, but avoid making every surface bright red.

Suggested palette (approximate starting point; sample the supplied logo asset if available):
- Primary red: `#E3262E`
- Deep red: `#B91F2A`
- Warm accent orange: `#F47721`
- Near-black: `#171719`
- Slate text: `#4B5563`
- Off-white background: `#F7F7F5`
- White surface: `#FFFFFF`
- Border: `#E5E7EB`
- Success: muted green
- Warning: amber
- Critical: red

Use red for identity, primary actions, active states, and important readiness indicators. Use neutral surfaces for most content. Do not make the entire dashboard a red wall.

## Visual personality
- Operational, confident, precise, calm under pressure.
- More like a modern facilities / safety operations product than a generic startup landing page.
- Strong hierarchy and generous spacing.
- Clear labels, readable tables, practical cards, and meaningful status indicators.
- Use simple line icons consistently.
- Use diagrams or small process visuals where they explain a workflow.
- Avoid excessive gradients, glassmorphism, floating blobs, random illustrations, and oversized marketing copy.
- Avoid generic AI-generated dashboard patterns and unnecessary decorative charts.

## Typography
Use a clean, highly legible sans-serif family. Prefer an available project font; otherwise use a modern system sans-serif. Use a strong, restrained heading scale and readable body text.

## Interface principles
1. **Clarity before decoration.** A user should understand the next action quickly.
2. **Mobile-first emergency page.** The QR destination must be legible and usable on a phone.
3. **Desktop-first admin dashboard.** Admins need a compact operational overview.
4. **Status must be explicit.** Use labels such as Due, Overdue, Needs Attention, In Progress, Resolved.
5. **Actions should be traceable.** Show who owns an issue and what happens next.
6. **Consistent components.** Buttons, cards, badges, tables, forms, and navigation should share a design system.
7. **Honest demo data.** Mark simulated metrics or seeded activity as demo data.

## Suggested layout
- Public site: simple top navigation, clear hero, short product explanation, product workflow, audience strip, footer.
- Admin app: persistent left navigation, top bar with institution/building context, main content area, concise metric cards, recent activity.
- Emergency page: minimal header, high-contrast emergency information, large contact/action affordances, clear floor/assembly-point details.

## Brand language
Prefer:
- Emergency readiness
- Preparedness
- Drill performance
- Safety inspection
- Corrective action
- Building emergency information
- Readiness status

Avoid:
- “Guaranteed safety”
- “100% compliant”
- “AI-powered life-saving prediction” (unless actually implemented and validated)
- “Real-time evacuation tracking” (unless genuinely implemented)
- “Prevents all disasters”

## Logo handling
Use the supplied logo file as an image asset. Maintain aspect ratio and sufficient clear space. Do not stretch, crop, recolor, or add effects to the original logo. If the logo asset is not present in the repository, ask the user to provide it or use a temporary text wordmark—do not invent a file path.
