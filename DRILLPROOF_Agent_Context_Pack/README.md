## Non-negotiable project rules
- Build a coherent, working prototype, not a pretend enterprise platform.
- Keep the product focused on **institutional emergency preparedness before an incident**.
- Support multiple hazard types. Fire is a key example, not the only supported emergency.
- Do not claim that the app detects fires, tracks people automatically, dispatches emergency services, or certifies legal compliance.
- Prefer working, testable flows over decorative complexity.
- Do not introduce blockchain, IoT hardware, sensor integrations, or AI features unless explicitly requested.
- Preserve the existing project structure and working functionality. Make focused changes.
- Use realistic sample data and label simulated/demo data honestly.

## Product one-liner
**DRILLPROOF helps institutions turn emergency plans into practiced, measurable, and continuously improved readiness.**

Tagline: **Prepared. Proven.**
